**D3 — /v1/sync sözleşmesi (K2-E1).** `POST /v1/sync`, gövde: `{ clientId, clientHlc, sinceCursor: {xid, seq} | null, ops: [...] }`; yanıt: `{ serverHlc, nextCursor, hasMore, resyncRequired, applied: [IngestResult...], changes: [...], snapshot: [...] | null }`. FluentValidation (K-G2 ilk kuruluş): YALNIZ yapısal — `ops` null değil, `ops.Count ≤ 100` (üstü **400**, hiçbir op işlenmez), `sinceCursor` alanları negatif değil. **Semantik doğrulama Domain'de kalır** (RejectedInvalid op-düzeyi sonuçtur; batch'i DÜŞÜRMEZ — K2-E5).
- **Akış modeli (pin — M5):** boş `ops[]` (salt-pull) LEGALDİR. Kilit/dedup/saat HEP `op.clientId`'den; `request.clientId` yalnız `serverHlc` fallback'i içindir. `op.actorId ↔ ICurrentUser` eşitliği ZORLANMAZ (push-authz adlandırılmış-ertelenmiş, M-G; testler actorId=sahte-user kullanır). Zehirli op yalnız kendi txn'ini düşürür; batch devam eder.

**D5 — Pull: xmin-ufku imleci (K2-E2) — RAW SQL, EF LINQ DEĞİL.**
```sql
SELECT * FROM outbox_messages
 WHERE commit_xid < pg_snapshot_xmin(pg_current_snapshot())
   AND (commit_xid, server_seq) > (@sinceXid::xid8, @sinceSeq)
   AND owner_id = @actorId
 ORDER BY commit_xid, server_seq LIMIT 500;
```
`nextCursor` = son dönen satırın `(commit_xid, server_seq)`; `hasMore` = tam-500 döndü. Artımlı istek `READ COMMITTED` (taze ufuk). **Parametre tipi (pin — M1):** Postgres'te `bigint→xid8` cast'i YOKTUR; `sinceXid` ya `NpgsqlParameter { NpgsqlDbType = NpgsqlDbType.Xid8, Value = (ulong)... }` ile cast'siz, ya **text parametre + `::xid8`** geçilir — bigint parametre geçme (runtime hatası). Satır-değer karşılaştırması `(commit_xid, server_seq) > (…)` xid8 btree ile geçerli (PG13+). **Yetki (K2-E3, 2b1 gerçeklemesi):** filtre `owner_id = actorId`; `actorId` **`ICurrentUser` portundan** — implementasyon auth diliminde YOK → endpoint **deny-by-default**: `ICurrentUser.UserId == null` → **401** (testler WAF'ta sahte `ICurrentUser` DI'lar). Pull-authz'ın collaborator/Y1-muafiyet tarafı **collab/auth dilimine adlandırılmış-erteleme** (owner-only dünyada Y1 senaryosu kurulamaz — spec bunu AÇIKÇA sınırlar, sessiz bırakmaz).
- **resyncRequired (K2-C6):** `sinceCursor < (gc_horizon_xid, gc_horizon_seq)` (sync_gc_state; horizon NULL ise tetiklenmez) → artımlı DÖNMEZ, `resyncRequired:true` (istemci snapshot ister).

**D6 — Tam-snapshot + devam-imleci (K2-E4, BLOKER-R1).** `sinceCursor == null` → snapshot isteği. **Sıra (pin — M5):** önce `ops[]` op-başına işlenir ve commit'lenir → SONRA snapshot txn'i açılır (istemcinin kendi push'u snapshot'ta görünür). Sunucu **tek `REPEATABLE READ` txn'de**: (a) `horizon = pg_snapshot_xmin(pg_current_snapshot())` yakala, (b) durumu **entity-PK sıralı** oku (2b1 owner-filtresi: aktörün outbox'ta `owner_id` olduğu `aggregate_id` kümesi — durum tablolarında owner kolonu yok; entity diliminde doğal filtreye döner, adlandırılmış), (c) iç-batch'lerle topla, TEK yanıtta dön. **Yanıt (pin):** `snapshot:[...]` + `nextCursor=(horizon,0)` + `hasMore=false` + `changes=[]` + `resyncRequired=false`. **Snapshot kaydı şekli (pin — M9):** entity başına `{ entityType, entityId, scalars: [{field, value, hlc, winOperationId}], sets: [{setName, elements: [{element, activeTags: [{tag, hlc}]}]}], groups: [{group, fields, hlc, winOperationId}] }` — orset'te **aktif add-tag id'leri ŞART** (istemci ileride `observed[]`'i bunlardan kurar; cancelled/tombstone satırları snapshot'a GİRMEZ, açıkça). **Devam-imleci = `(horizon, 0)`** — ufkun KENDİSİ, SON SATIR DEĞİL. HTTP-düzeyi snapshot sayfalaması YOK (yön). `server_seq ≥ 1` değişmezi sayesinde `(horizon,0)` hiçbir gerçek satırla çakışmaz — H7b assert eder.
